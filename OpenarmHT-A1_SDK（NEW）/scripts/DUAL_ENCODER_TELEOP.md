# OpenArm 双臂编码器遥操

直接运行 `python 5_teleop_control.py`，不需要任何参数、选择菜单或输入确认文字。
该命令会连接设备并让两条从臂回零。启动前两条主臂自然下垂、夹爪闭合并保持不动。

| 设备 | CAN 口 | ID |
| --- | --- | --- |
| 左从臂 | CAN1 | 1–7 关节，8 夹爪 |
| 右从臂 | CAN2 | 1–7 关节，8 夹爪 |
| 左编码器主臂 | CAN3 | 1–7 关节，8 夹爪 |
| 右编码器主臂 | CAN4 | 1–7 关节，8 夹爪 |

接线和两侧独立的方向符号位于 `../robot_param/dual_encoder_teleop.yaml`。
右侧保留原单臂版的七轴 `-1` 及夹爪 `-1`，包含 J3/J5 的修正。
新增左侧暂使用相同符号，尚未实机逐轴验证，不能将离线通过视为方向已经确认。

启动先检查四组共 32 个反馈，再同时让两条从臂及夹爪回零。
回零完成后同时采集两条主臂各 20 帧反馈，以各自的中位数作为本次软件基准。
采样过程中任一编码器移动超过 0.05 rad 会退出。程序不写入硬件零位。
如需把两条编码器主臂的当前姿态分别保存为硬件零位，请依次运行：

```bash
python 0_can3_encoder_set_zero.py --can-port 3  # 左编码器主臂
python 0_can3_encoder_set_zero.py --can-port 4  # 右编码器主臂
```

两条命令都只连接所选编码器主臂，写入 ID1–8，不连接 CAN1/CAN2 从臂。
不传参数仍默认操作 CAN3，以兼容原有用法。本双臂遥操不要求先运行硬件置零脚本。

两个从臂使用 MIT 模式及各自 URDF 的重力补偿，位置相对基准 1:1 跟随，
速度前馈按各侧 YAML 限幅。关节目标在机械限位内留 0.05 rad，夹爪按其 YAML 行程夹紧。
触限时只限制对应关节，不中断另一侧。此处没有新增 QP 或双臂碰撞规划。

一个 SDK 实例管理四个 CAN 口，每周期先验证/计算两侧目标，再统一调用一次发送。
两条主臂只排队查询，两个从臂及夹爪同时排队 MIT；目标周期 5.2 ms，实际频率显示在终端。
这是软件同周期更新，不承诺不同 CAN 口的硬件时钟同步。SDK 自身初始化/析构按底层实现执行；
析构使用原生 brake 分支，不使用会 reset 所有设备的分支。

第一次 Ctrl+C 或主臂反馈异常：退出跟随，在从臂反馈有效的前提下双臂回零后停止。
第二次 Ctrl+C：中断回零，发送双臂软件停止。
任一从臂故障、反馈过期或持续跟随误差过大：停止两条从臂，不继续回零。
软件停止不等于硬件急停。

原右臂实现保存在 `encoder_teleop_single.py`，供兼容接口及回溯使用；其旧 CAN3→CAN2
接线与当前双臂接线不同。当前双臂入口是 `5_teleop_control.py`。

离线验证：`python -m unittest -v test_dual_encoder_teleop.py`。
测试禁止构造真实 SDK，覆盖配置原生解析、重号 ID 分组、左右独立基准/夹爪、同步发送、
回零、反馈失效及两次中断。实机方向、频率和运动效果需要现场验证。
